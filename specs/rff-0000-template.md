## User problem and context

Who has the problem, on which supported platform/version, and what evidence
shows the problem exists? Use synthetic examples; omit personal or operational
secrets.

## Desired outcome

Describe the measurable user benefit without assuming a particular design.

## Proposed capability and non-goals

State the smallest useful behavior, explicit exclusions, and a manual/offline
fallback if the feature is unavailable.

## Data, privacy, and security

List data collected/derived/transmitted, peer and key assumptions, authorization
boundary, possible harms, safe defaults, logs/retention, and an incident/disable
path. Identify any new network listener, external service, hardware, or dependency.

## Maintenance and compatibility

Name the maintainer role, upgrade/deprecation plan, resource cost, API/config
compatibility impact, and rollback route.

or commit, stable URL, access date, and limits of the evidence.

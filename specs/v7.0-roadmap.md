# CPIP v7.0.0 proposal roadmap

| Field | Value |
|-------|-------|
| Status | Proposed |
| Version Target | v7.0.0 |
| Scope | RFF-0001–0003; RFC-0027–0036 |

This roadmap turns the v6.0 RFC drafts and the implementation audit into a staged, testable v7.0.0 release proposal. RFFs describe user outcomes; RFCs specify implementation contracts. An RFC marked Draft is not a claim that its feature is already shipped.

## Release goals

1. **Trustworthy status everywhere:** API, CLI, TUI, and dashboard distinguish unsupported, unconfigured, unavailable, disabled, and running providers (RFF-0001, RFC-0027).
2. **No silent security downgrade:** E2EE messages remain encrypted through queueing/retry and report delivery/decryption failures (RFF-0002, RFC-0028).
3. **Explainable, auditable detections:** cellular findings use source quality and uncertainty; accepted detections can be verified in a persistent evidence chain (RFF-0003, RFC-0029, RFC-0032).

## Release gates

- Core RFCs pass hardware-independent tests with deterministic fixtures and no network access.
- Unsupported optional backends return an explicit capability state; they do not simulate success.
- RF transmission, cloud calls, external notarization, and threat sharing remain opt-in and are not started as a side effect of importing or starting the server.
- Every mutating API action has matching CLI/API behavior, authorization coverage, and an error response that is not HTTP success.
- Dashboard and TUI show backend limitations without presenting draft RFC functionality as active.

## Deferred beyond v7.0

Full PQ mesh ratcheting/signatures (RFC-0019), DHT-based global threat intelligence (RFC-0026), production carrier/eSIM actions (RFC-0018), SS7 network filtering/SigFW deployment (RFC-0005), Bluetooth/NFC/audio/LiFi transports (RFC-0015), cloud AI/TTS (RFC-0013), automated key destruction or reboot on duress (RFC-0020), and transmitter-based spectrum/Faraday operations (RFC-0004/0017) require independent security reviews, external systems, or physical test rigs. v7.0.0 must report these as unavailable until those prerequisites exist. RFC-0036's extended-rank KEMs are experimental implementation options, not additional standardized security levels.
